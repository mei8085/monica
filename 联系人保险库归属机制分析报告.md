```php
public function execute(array $data): Contact
{
    $this->data = $data;
    $this->validate();        // 权限验证
    $this->createContact();   // 创建联系人
    $this->updateLastEditedDate();
    $this->createFeedItem();
    return $this->contact;
}

private function createContact(): void
{
    // 模板继承：优先使用传入的模板，否则使用保险库默认模板
    $templateId = $this->valueOrNull($this->data, 'template_id');
    if (! $templateId) {
        $templateId = $this->vault->default_template_id;
    }

    $this->contact = Contact::create([
        'vault_id' => $this->data['vault_id'],  // 直接分配
        'first_name' => $this->valueOrNull($this->data, 'first_name'),
        // ... 其他字段
        'template_id' => $templateId,  // 继承保险库默认模板
    ]);
}
```

```php
private function remove(): void
```

## 4. 联系人迁移场景与一致性维护

### 4.1 迁移操作类型

系统支持两种联系人迁移方式：
1. **移动（Move）**：联系人从源保险库彻底移动到目标保险库
2. **复制（Copy）**：在目标保险库创建联系人副本，源保险库保留原记录

### 4.2 移动联系人（Move）

[MoveContactToAnotherVault.php](file:///d:/fz/0601-1/solo-dogfeeding/code/28-monica/app/Domains/Contact/ManageContact/Services/MoveContactToAnotherVault.php#L49-L116)：

```php
public function execute(array $data): Contact
{
    $this->data = $data;
    $this->validate();                // 1. 权限验证
    $this->move();                    // 2. 更新联系人归属
    $this->moveCompanyInformation();  // 3. 处理关联公司
    $this->updateLastEditedDate();    // 4. 更新时间戳
    return $this->contact;
}
```

#### 4.2.2 关联数据一致性处理（公司信息）

[MoveContactToAnotherVault.php](file:///d:/fz/0601-1/solo-dogfeeding/code/28-monica/app/Domains/Contact/ManageContact/Services/MoveContactToAnotherVault.php#L90-L109)：

```php
private function moveCompanyInformation(): void
{
    if ($this->contact->company) {
        if ($this->contact->company->contacts->count() === 1) {
            // 情况A：公司只有这一个联系人 → 直接移动公司到新保险库
            $this->contact->company->vault_id = (string) $this->newVault->id;
            $this->contact->company->save();
        } else {
            // 情况B：公司有多个联系人 → 在新保险库创建公司副本
            $newCompany = (new CreateCompany)->execute([
                'account_id' => $this->author->account_id,
                'author_id' => $this->author->id,
                'vault_id' => $this->newVault->id,
                'name' => $this->contact->company->name,
                'type' => $this->contact->company->type,
            ]);

            $this->contact->company_id = $newCompany->id;
            $this->contact->save();
        }
    }
}
```

## 7. 架构总结与设计亮点

### 7.1 核心关系图

```
Account (1) ────> (N) Vault (1) ────> (N) Contact
                   │                    │
                   │                    │
                   │                    │
                   (N)                (N)
                   │                    │
                   │                    │
                   └──── user_vault ────┘
                            │
                      permission, contact_id
                            │
                           User (N)

另外：
Contact (1) <─── (M) contact_vault_user (N) ───> (1) User
                      └─ is_favorite, number_of_views
```

### 7.2 设计亮点

1. **单一归属原则**：联系人通过 `vault_id` 明确归属单个保险库，避免多归属带来的复杂性
2. **显式上下文传递**：`vault_id` 通过 URL 路由传递，创建时用户已在保险库上下文中
3. **数据库级约束**：大量使用外键级联删除，保证数据一致性
4. **统一权限校验**：通过 `BaseService` 实现声明式权限验证
5. **关联数据智能迁移**：移动联系人时根据公司关联数量决定移动或复制策略

### 7.3 潜在风险点

1. **复制操作局限性**：`CopyContactToAnotherVault` 仅复制联系人基本信息，不复制关联数据（备注、标签、关系等）
2. **缺少事务包裹**：迁移操作（如 `MoveContactToAnotherVault`）未使用数据库事务，极端情况下可能出现部分成功
3. **收藏数据孤岛**：`contact_vault_user` 表记录了保险库ID，但联系人移动后原保险库的收藏/查看记录无法迁移
